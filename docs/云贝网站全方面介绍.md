# 云贝网站全方面介绍

## 一、项目定位

云贝是一个面向 AI API 中转、模型接入、余额管理和应用启动的综合服务网站。它的核心目标，是把多个上游 AI 模型服务、不同供应商的 API 能力、用户余额、模型费率、API Key、使用日志和充值兑换流程，统一整理成一个对普通用户友好、对管理员可维护、对开发者可扩展的 AI 服务入口。

从用户视角看，云贝不是一个单纯的后台管理系统，而是一个可以帮助用户快速开始使用 AI 的门户。公开首页采用沉浸式整屏换页体验，而不是传统向下滚动；背景粒子图会自动变化，并会在首页换页时主动触发一次粒子形态切换。用户注册或登录后，首先进入与首页视觉和交互一致的“快速启动”页面，通过一页一页选择用途、选择模型、查看费率、检测余额、充值或兑换、查看客户端下载入口，最后进入用户后台，从而完成从注册到账户可用的第一段路径。

从运营和维护视角看，云贝保留了底层 New API 的核心能力，包括渠道管理、用户管理、兑换码管理、倍率与价格管理、日志审计、钱包充值、系统设置等后台能力。普通用户看到的是收敛后的刚需功能，管理员则可以进入完整后台维护平台运行。

从技术视角看，云贝是在 New API 网关能力之上做的产品化前端体验层。它保留了原有开源项目的工程归属和授权信息，同时将面向用户的品牌、流程、导航和新手教程改造成“云贝”体验。

## 二、适用对象与使用内容

### 1. 普通用户

普通用户主要使用云贝来完成以下事情：

1. **注册和登录账户**  
   用户从登录页可以看到公开注册入口：“没有账号？立即注册”。注册成功后，用户会进入快速启动流程，不需要先面对复杂的后台管理页面。

2. **选择 AI 使用用途**  
   云贝会先让用户选择使用 AI 的主要场景，目前包括：
   - Web Coding：代码生成、网页开发、调试、工程协作等。
   - 聊天：日常对话、写作、总结、翻译、知识问答等。
   - 生图等其他：图像生成、多模态创作、创意探索和其他模型能力。

3. **选择模型并查看费率**  
   快速启动页会展示平台支持的模型，并在模型下方显示费率信息。费率展示方式保持 OpenRouter 风格，便于用户理解输入、输出、模型倍率和成本。

4. **检测账户余额**  
   云贝会根据用户当前余额判断是否足够启动。如果余额足够，用户可以直接进入下一步；如果余额不足，页面会引导用户充值或使用兑换码。

5. **充值与兑换码**  
   普通用户可以进入钱包页面查看余额、充值状态、推荐奖励和兑换码区域。兑换码功能对普通用户开放，用户可以输入管理员发放的兑换码为账户增加额度。

6. **下载云贝客户端**  
   快速启动页预留 macOS 和 Windows 下载卡片。当前 UI 已完成，下载动作和安装包资源可在后续阶段接入。

7. **使用 API Key 和日志功能**  
   用户可以创建和管理 API Key，查看用量日志，并根据自己的应用场景进行接入。

### 2. 管理员 / Root 用户

管理员主要使用云贝来维护平台，包括：

1. **维护用户账户**  
   查看用户、调整用户状态、管理用户角色、处理用户余额与权限问题。

2. **维护模型和渠道**  
   配置不同上游供应商、模型名称、渠道状态、分组权限、故障切换和可用性策略。

3. **维护价格与倍率**  
   设置模型倍率、分组倍率、渠道成本、计费规则和面向用户的价格显示。

4. **创建和管理兑换码**  
   管理员可以生成兑换码，普通用户则通过钱包页面使用兑换码。

5. **审计日志与运行状态**  
   查看 API 请求日志、用量日志、任务日志、绘图日志、系统健康和渠道状态。

6. **维护站点设置**  
   管理站点名称、Logo、注册开关、登录方式、公告、法律协议、支付配置、钱包配置、聊天预设等。

## 三、核心功能介绍

### 1. 公开首页

公开首页是云贝面向未登录用户和回访用户的第一层品牌入口。它现在采用“整屏分页 / 换页”交互，而不是传统的页面向下滚动。

首页目前由三页组成：

1. **首页主视觉**  
   展示云贝品牌、核心价值、登录 / 注册 / 进入快速启动等主要行动入口。

2. **模型广场**  
   用公开叙事方式展示云贝可以接入和管理多类 AI 模型能力，帮助用户理解平台不是单一模型入口。

3. **关于云贝**  
   说明云贝的定位、能力边界和开源归属，并在页面底部保留 New API / QuantumNous attribution。

首页交互特点：

- 页面切换是一屏一屏切换，不依赖页面整体纵向滚动。
- 支持“下一步 / 上一步”按钮切页。
- 支持鼠标滚轮、触摸滑动、键盘方向键、PageUp / PageDown、空格等方式切页。
- URL hash 会随页面同步，例如 `#home`、`#models`、`#about`。
- 背景使用会自动变化的粒子图，并且每次首页页面切换时都会主动触发一次粒子 morph，让页面切换和背景变化形成联动。

### 2. 快速启动页面

“快速启动”是云贝面向普通用户的第一个登录后页面。它承担新手教程、产品引导和首次使用路径的作用。

快速启动现在采用和公开首页一致的整体体验：

- 同样是整屏分页 / 换页，不是后台表单式长页面。
- 同样使用深色沉浸背景、云贝 Logo、玻璃拟态卡片和粒子背景。
- 同样通过“下一步 / 上一步”完成页面切换。
- 同样在切换页面时触发背景粒子 morph。
- 进入快速启动时不会显示现有后台的顶部栏和侧边栏，等用户完成快速启动或点击“进入后台”后，才进入现有用户后台。

页面分为五步：

1. **选择使用 AI 的用途**  
   让用户明确自己要用云贝做什么，从而降低第一次使用的理解成本。当前用途包括 Web Coding、聊天、图片与更多能力。

2. **选择要用的模型**  
   展示当前支持的模型列表、模型供应商、模型能力标签和 OpenRouter 风格费率信息。

3. **检测账户余额**  
   自动判断余额是否足够启动。如果不足，引导用户进入钱包充值或使用兑换码。

4. **下载云贝轻松开启**  
   展示 macOS 与 Windows 两个客户端入口。目前下载 UI 已完成，安装包资源可在后续阶段接入。

5. **完成并进入下一阶段**  
   汇总用户选择的用途、模型和余额状态。用户可以在最后一页继续启动所选工作流，也可以通过“下一步”或“进入后台”进入现有用户后台。

快速启动页面底部始终提供：

- 上一步
- 当前页码 / 总页数
- 直接进入后台
- 下一步；最后一页的下一步会进入后台

### 3. 普通用户导航收敛

云贝将普通用户登录后的后台页面进行收敛，只保留刚需功能：

- 快速启动
- Playground
- Chat
- API Keys
- Usage Logs
- Wallet / Top up
- Redeem codes
- Profile

这样普通用户不会被管理员后台中的渠道、系统设置、用户管理、模型管理等复杂页面干扰。

### 4. 管理员完整后台

管理员仍保留完整 New API 后台能力，可以继续进行平台级维护。这种设计保证了两类用户的体验分离：

- 普通用户：只看到使用 AI 所需的入口。
- 管理员：保留完整运营和维护能力。

### 5. 兑换码体系

云贝的兑换码体系采用“管理员生成、普通用户使用”的路径：

- 管理员在后台创建和管理兑换码。
- 普通用户在钱包页面使用兑换码。
- 普通用户访问管理员兑换码管理页时，会被自动引导到钱包兑换区域。

这保证了兑换码既能作为运营工具，也不会把管理权限暴露给普通用户。

### 6. 钱包与余额体系

钱包模块承担以下功能：

- 展示当前余额。
- 展示充值入口。
- 展示订单或交易状态。
- 提供兑换码输入区域。
- 展示推荐奖励或相关收益信息。

余额是用户能否启动 AI 使用流程的重要判断条件，快速启动页会直接读取余额状态并给出引导。

### 7. 模型与费率展示

云贝会把可用模型以用户可理解的方式列出来，包括：

- 模型名称
- 供应商名称
- 模型能力标签
- 输入费率
- 输出费率
- 适用场景

费率展示保持 OpenRouter 风格，方便用户将云贝与常见模型平台进行成本理解上的对齐。

### 8. API Key 与开发接入

对于开发者或需要接入应用的用户，云贝保留 API Key 管理能力。用户可以创建自己的 Key，并将其用于：

- Web 应用
- 本地客户端
- Agent 工具
- 编程 IDE
- 第三方聊天客户端
- OpenAI-compatible SDK

云贝的目标是让用户用统一接口访问多个模型，而不用分别处理不同供应商的接入差异。

## 四、功能和维护路径

### 1. 用户使用路径

普通用户的标准路径如下：

```text
打开网站 → 首页整屏换页浏览 → 登录 / 注册 → 快速启动整屏分页 → 选择用途 → 选择模型 → 检查余额 → 充值或兑换 → 查看客户端下载入口 → 完成快速启动 → 进入用户后台
```

如果用户已经熟悉平台，也可以在快速启动任意页面点击“进入后台”，直接跳过新手流程进入现有后台。

这条路径把用户第一次接触平台时最容易困惑的几个问题串起来：

- 我能用它做什么？
- 我该选哪个模型？
- 价格怎么算？
- 余额够不够？
- 不够钱怎么处理？
- 最后从哪里开始？

### 2. 管理员维护路径

管理员维护路径如下：

```text
登录管理员账户 → 进入后台 → 配置渠道 / 模型 / 价格 / 用户 / 兑换码 / 支付 / 系统设置 → 查看日志和健康状态 → 持续调整运营策略
```

管理员重点维护以下几类资源：

1. **模型资源**  
   确保模型列表准确、可用，并配置对应倍率和供应商信息。

2. **渠道资源**  
   确保上游 API 渠道可用，必要时配置多渠道、备用渠道和自动故障切换。

3. **用户资源**  
   处理用户注册、状态、权限、余额、分组和异常请求。

4. **兑换码资源**  
   根据运营活动或人工充值需求生成兑换码，并追踪使用情况。

5. **钱包和支付资源**  
   配置充值方式、兑换码开关、推荐奖励、订单处理和合规状态。

6. **日志审计资源**  
   查看使用日志、请求日志、异常日志和模型调用分布，及时发现问题。

### 3. 产品维护路径

云贝后续产品维护可以按以下阶段推进：

#### 第一阶段：普通用户体验完善

- 持续优化首页三屏文案、模型广场叙事和 About 信息层级。
- 持续优化首页换页手感、移动端触摸切换和粒子 morph 节奏。
- 完善快速启动文案。
- 完善模型推荐逻辑。
- 优化余额不足时的引导。
- 接入真实 macOS / Windows 下载资源。
- 让注册后新用户更顺畅地完成快速启动并进入后台。

#### 第二阶段：支付与兑换链路完善

- 接入正式支付方式。
- 完善兑换码生成、发放、核销和统计。
- 加强充值失败、订单超时、支付回调异常的处理。
- 完善钱包交易记录。

#### 第三阶段：模型广场与价格体系完善

- 展示完整模型列表。
- 按能力分类模型，例如代码、聊天、图片、推理、视觉、语音、视频。
- 增加模型推荐标签。
- 对齐 OpenRouter 风格价格说明。
- 支持不同用户组或套餐的差异化价格。

#### 第四阶段：客户端下载和配置自动化

- 接入 macOS 安装包。
- 接入 Windows 安装包。
- 支持下载后自动配置 API 地址和 Key。
- 支持一键打开第三方客户端或协议链接。

#### 第五阶段：运营和审计增强

- 增加用户转化漏斗。
- 增加充值和兑换统计。
- 增加模型调用成本分析。
- 增加渠道健康评分。
- 增加异常请求检测和告警。

## 五、技术架构介绍

### 1. 总体架构

云贝基于前后端分离架构，整体可以理解为：

```text
用户浏览器 / 客户端
        ↓
React 前端界面
        ↓
New API 后端服务
        ↓
数据库 / Redis / 上游 AI 模型供应商
```

前端负责用户界面、导航、快速启动、钱包展示、模型展示、注册登录和管理后台交互。后端负责认证、用户、余额、渠道、模型、计费、日志、兑换码和 API 中转。

### 2. 前端技术栈

云贝当前前端位于：

```text
web/default
```

主要技术栈包括：

- React 19
- TypeScript
- TanStack Router
- TanStack Query
- Zustand
- React Hook Form
- Zod
- Tailwind CSS
- Base UI
- Rsbuild
- Bun
- i18next / react-i18next

前端核心职责：

1. 渲染公开首页、登录页、注册页、快速启动页和后台页面。
2. 为公开首页和快速启动提供一致的整屏分页、粒子背景和切页交互。
3. 根据用户角色显示不同导航。
4. 通过路由守卫控制登录态访问。
5. 通过 API 获取系统状态、用户信息、模型价格和钱包信息。
6. 支持中英文等多语言文案。
7. 保持普通用户和管理员的体验分离。

### 3. 后端技术栈

底层后端来自 New API 项目，主要技术栈包括：

- Go
- Gin Web Framework
- GORM
- SQLite / MySQL / PostgreSQL
- Redis / 内存缓存
- JWT / Session 相关认证机制
- 多供应商 AI API relay 适配层

后端核心职责：

1. 用户注册、登录和权限验证。
2. 用户余额、额度和用量统计。
3. API Key 创建和管理。
4. 渠道和模型配置。
5. 上游模型请求转发。
6. 请求日志和计费结算。
7. 兑换码生成、管理和核销。
8. 系统设置、公告、支付、OAuth 和安全配置。

### 4. 路由架构

前端使用 TanStack Router，核心路由分为：

1. **公开路由**
   - 首页
   - 登录
   - 注册
   - 关于
   - 价格 / 模型广场
   - 隐私协议 / 用户协议

2. **登录态路由**
   - 快速启动
   - 钱包
   - API Keys
   - 使用日志
   - Playground
   - Chat
   - Profile
   - Dashboard Overview
   - 管理员后台页面

3. **权限控制路由**
   - 普通用户访问管理页会被拦截或重定向。
   - 管理员保留完整后台访问能力。

### 5. 权限与角色设计

云贝当前沿用数字角色模型：

- 普通用户：普通使用权限。
- 管理员：后台维护权限。
- Root：最高权限。

前端根据用户角色决定：

- 登录后默认跳转哪里。
- 侧边栏显示哪些菜单。
- 是否允许访问兑换码管理页。
- 是否允许访问完整系统后台。

后端仍应作为最终权限校验来源，前端控制主要用于用户体验和减少误操作。

### 6. 数据流

普通用户登录后的关键数据流如下：

```text
用户登录 / 注册
  ↓
前端调用认证接口
  ↓
后端返回登录状态和用户信息
  ↓
前端保存用户信息
  ↓
根据角色跳转 quick-start 或 dashboard
  ↓
quick-start 以全屏分页方式拉取模型价格、用户余额、系统状态
  ↓
用户选择用途、模型、充值或兑换
  ↓
完成快速启动或点击直接进入后台
  ↓
进入 dashboard overview，再继续使用 API Key / Chat / Playground / Wallet 等功能
```

公开首页和快速启动的前端交互数据流还包括一条 UI 状态链路：

```text
用户点击下一步 / 上一步 / 滚轮 / 触摸 / 键盘
  ↓
分页框架更新当前页面索引
  ↓
URL hash 同步到当前页面
  ↓
触发粒子背景 morphSignal
  ↓
PointCloudMorphCanvas 执行一次粒子形态切换
```

### 7. 模型调用链路

模型调用链路可以理解为：

```text
用户应用 / 客户端
  ↓
云贝 API Key
  ↓
New API relay endpoint
  ↓
渠道选择 / 分组 / 倍率 / 余额预扣
  ↓
上游模型供应商
  ↓
返回模型响应
  ↓
日志记录 / 费用结算 / 余额更新
```

这种架构的优势是：

- 用户只需要一个统一入口。
- 运营可以在后端调整上游渠道。
- 可以做统一计费和日志审计。
- 可以通过分组、渠道和倍率控制不同用户的模型访问能力。

## 六、品牌与开源归属

云贝是面向用户的产品化品牌名称。它用于网站公开视觉、用户引导、快速启动、下载入口和运营文案中。

生产环境由 Docker Compose 管理，当前核心容器包括：


其中：

### 2. 与原 New API 的关系

云贝仍以 New API 为底座，保留以下底层能力：

- OpenAI-compatible API relay。
- 用户、token / API Key、分组、余额、日志。
- 渠道、模型、倍率、价格和请求计费。
- 管理员后台、系统设置、钱包 / 充值 / 兑换码。
- 多供应商模型适配和故障处理基础能力。

云贝在 New API 基础上主要做了这些产品化和运维化改造：

1. **品牌与前端体验**：公开首页、登录后快速启动、粒子背景、整屏分页、新手使用路径、普通用户导航收敛。
2. **Channel Console / 渠道运营能力**：增加更适合运营排障的渠道健康、模型同步、价格同步和手动重算能力。
3. **价格状态修复**：把“部分模型未知价格”从整条渠道失败中拆出来，已知价格模型可以继续使用，未知价格模型以 warning 呈现。
4. **原后台兼容修复**：修复原 New API 渠道管理页因前端认证缓存 / uid 状态不一致导致跳 403 的问题。
5. **代理能力外挂化**：生产上采用独立 `CliProxy API` 容器，后续凭证和 proxy 能力优先向外挂 API 方式演进，减少主站内置代理逻辑引入的状态耦合。
6. **安全与部署防护**：增加 SSRF 校验、webhook 日志脱敏、Caddy 安全头、Docker healthcheck、compose 必填变量保护和服务器权限收紧。

### 3. 本次修复的两个关键 bug

#### 3.1 计费渠道匹配问题

问题表现：

```text
模型已经能从上游同步到云贝，但价格没有自动匹配 root 的计费渠道，导致调用时提示“没给模型配价格”。
```

修复结果：

- 已知价格模型会同步并启用。
- 未知价格模型不会再把整条渠道标记为 failed。
- 渠道价格状态支持 `warning`，用于表达“部分模型没有价格”。
- 新增手动价格重算接口：

```http
POST /api/channel-console/channels/:id/resync-prices
```

生产验证中，渠道 1 的最终状态为：

```text
health_status=healthy
model_sync_status=healthy
price_sync_status=warning
```

其中：

```text
已同步并启用价格模型：11
未知价格模型：22
```

这表示当前渠道整体可用；剩余 22 个未知价格模型后续需要继续补价格或 fallback 规则。

#### 3.2 原 New API 渠道界面 403

问题表现：

```text
管理员点击原 New API 自带渠道界面时，前端直接跳转到 403。
```

排查结论：

- 更像是前端路由守卫读取旧缓存用户角色 / uid 状态导致的误判。
- 后端 `/api/channel/` 管理员接口本身在生产验证中返回 HTTP 200。

修复结果：

- 登录态写入时同步 `localStorage.uid`。
- logout / reset 时清理 `uid`。
- 管理员页面进入前强制刷新 `/api/user/self`。
- 兼容 `/api/channel` 无尾斜杠路径。

### 6. 后续架构建议

1. 继续把凭证管理 / proxy 能力向外挂 `CliProxy API` 形式收敛，主站只保留必要的调用、状态展示和权限控制。
2. 给 `cli-proxy-api` 固定镜像版本或 digest，避免 `latest` 带来不可控变更。
3. 后续为 22 个未知价格模型补齐价格或配置 fallback 规则，让 `price_sync_status` 从 `warning` 进一步收敛为 `synced`。
4. 如果继续强化生产安全，建议把 Redis 密码等运行 secret 从 command / healthcheck 插值迁移到文件型 secret。
5. `deploy` 用户属于 docker 组，权限等价于高权限部署账号，应按 root 级密钥管理。
