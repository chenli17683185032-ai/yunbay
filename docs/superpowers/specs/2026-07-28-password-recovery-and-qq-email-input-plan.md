# 密码找回与 QQ 邮箱输入改造计划

日期：2026-07-28
项目：云贝网站
状态：已完成
当前阶段：实现、自动测试、生产构建、桌面/移动端浏览器验证与交付收尾均已完成

## 一、目标与性能指标

本次工作以用户可重复完成的认证闭环为目标，而不是只增加静态界面元素。

### 目标 1：密码找回闭环

用户从登录页进入“密码找回”，输入已注册邮箱并获取验证码，随后输入验证码和自定义新密码完成重置。

验收指标：

1. 登录页存在清晰可见的“密码找回”按钮，点击后进入 `/forgot-password`。
2. 密码找回页支持发送验证码、输入 6 位验证码、输入并确认新密码。
3. 新密码长度规则与注册规则一致：8-20 个字符。
4. 验证码保持 10 分钟有效、成功后立即失效，不能重复使用。
5. 未注册邮箱仍返回统一的发送成功响应，避免账号枚举。
6. 旧邮件链接 `/user/reset?email=...&token=...` 继续可用，避免破坏已有邮件和 classic 前端。
7. 用户自定义密码时，接口不把明文密码回传给前端。

### 目标 2：QQ 邮箱固定后缀输入

注册页只让用户填写 QQ 邮箱的本地部分，界面固定展示 `@qq.com`。

验收指标：

1. 注册页不再展示“只能填 QQ 邮箱”或同义提示。
2. 邮箱控件固定显示 `@qq.com`，用户输入框只接收前缀部分。
3. 发送验证码和注册请求仍提交完整邮箱，例如输入 `123456` 时提交 `123456@qq.com`。
4. 空值、包含 `@`、包含空格的前缀在前端被拒绝。
5. 后端现有 QQ 邮箱注册约束保持不变。

## 二、工程控制结构

### 被控对象

- 用户账号密码状态。
- 注册表单中的邮箱地址状态。

### 控制器

- 前端 React Hook Form + Zod 表单校验。
- 后端验证码签发、校验、密码更新逻辑。

### 测量

- 邮箱格式、验证码长度与有效性。
- 新密码长度、两次密码输入一致性。
- API 返回结果、数据库密码哈希变化、验证码是否被消费。

### 执行

- 发送密码重置验证码邮件。
- 调用密码更新接口写入新密码哈希。
- 将 QQ 邮箱前缀合成为完整邮箱后提交。

### 环境与扰动

- 邮件延迟或投递失败。
- Turnstile 尚未完成。
- 重复点击、验证码过期、错误验证码、并发重置。
- 历史邮件链接和 classic 前端仍调用旧请求格式。

### 稳定性策略

- 保留现有路由和请求字段 `email`、`token`，新增 `password` 为可选字段，维持向后兼容。
- 新流程提交自定义密码；旧调用未提交密码时仍走历史随机密码流程。
- 发送接口继续对“邮箱不存在”返回成功，减少信息泄露。
- 验证码只有密码写入成功后才删除，失败时允许用户纠正输入后重试。

## 三、现状与 GitHub 参考

### 本地现状

- `web/default` 登录页已有右上角小号 `Forgot password?` 文字链接，但不是清晰按钮。
- `/forgot-password` 只发送重置邮件，不提供验证码、新密码输入。
- 后端生成 UUID token，并通过邮件链接进入 `/user/reset`。
- `/api/user/reset` 当前由服务端随机生成 12 位密码并把明文返回前端。
- 注册页输入完整邮箱，并显示 `Email (QQ mailbox only)`、`Only QQ email addresses are supported`。

### GitHub 参考

- 检查了 `QuantumNous/new-api` 的认证实现：上游同样采用登录页文字入口、邮件链接、服务端随机密码方案。
- 上游保留 `/api/reset_password` 与 `/api/user/reset` 两个端点，本次沿用该分层，不新增重复路由。
- 本次在上游结构上做兼容扩展：发送邮件时提供可手输验证码，同时保留链接；重置接口允许客户端提交经过校验的新密码。
- shadcn/ui 当前项目为 Base UI、Tailwind v4、Nova 风格，`input-group`、`input-otp`、`button`、`form` 均已安装，改造直接复用现有组件。

## 七、测试矩阵

### 后端自动测试

1. 正确邮箱 + 正确验证码 + 合法新密码：密码更新成功。
2. 新密码可用于模型层密码校验。
3. 成功后验证码失效，第二次请求失败。
4. 错误验证码：密码不变。
5. 新密码少于 8 位或超过 20 位：请求失败，验证码不被消费。
6. 旧请求不含 `password`：继续生成随机密码并返回，保持兼容。

### 前端自动检查

1. 登录页存在 `/forgot-password` 的独立按钮和“密码找回”翻译键。
2. 找回表单包含邮箱、验证码、新密码、确认密码和对应 API 调用。
3. 注册邮箱使用 `InputGroupInput` 和固定 `@qq.com` 后缀。
4. 注册请求和验证码请求使用拼接后的完整 QQ 邮箱。
5. 旧“仅限 QQ 邮箱”提示从注册表单移除。

### 手工浏览器验证

1. 桌面宽度检查登录、注册、密码找回三页。
2. 手机宽度检查验证码控件、固定后缀和按钮不溢出、不重叠。
3. 验证 Tab 顺序、按钮禁用态、倒计时和密码错误提示。
4. 检查控制台无运行时错误，页面无明显布局抖动。

## 八、风险与回退

- 验证码仍存于进程内存，服务重启后失效；本次不扩大为 Redis/数据库改造。
- 6 位验证码比 UUID token 空间更小，依赖现有 CriticalRateLimit、10 分钟有效期和单次消费降低风险。
- 邮件服务失败时，接口为防止账号枚举仍可能返回成功；服务端日志继续记录实际投递错误。
- 若自定义密码路径出现问题，可回退前端 `password` 字段提交；后端旧随机密码路径仍保留。
