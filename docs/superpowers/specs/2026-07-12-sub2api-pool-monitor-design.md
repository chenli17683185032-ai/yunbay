# Sub2API 号池与模型可用性邮件监控规格

日期：2026-07-12

## 目标

在生产服务器上运行一个独立、确定性的监控脚本，每 5 分钟读取 Sub2API 的实时号池、渠道监测和账号额度数据。当号池或模型可用性低于 80%，或任一可读取额度窗口的使用率达到 80%，持续通过现有云贝 SMTP 链路发送邮件，直到异常解除。

## 运行态事实

- Sub2API 生产容器为 `yunbay-sub2api`，管理 API 位于容器网络内的 `/api/v1`。
- 管理账号由 Sub2API 容器的 `ADMIN_EMAIL` / `ADMIN_PASSWORD` 提供，脚本不得复制或记录其值。
- Sub2API 已启用渠道监测，并通过 `/admin/channel-monitors` 暴露主模型、附加模型、当前状态和七日可用率。
- Sub2API 已启用实时运维监控，并通过 `/admin/ops/account-availability` 暴露账号可用状态。
- OAuth / setup-token 账号可通过 `/admin/accounts/:id/usage?source=active` 获取额度窗口使用率。
- 云贝出站邮件配置保存在 new-api 的 `options` 表中，当前由 Resend SMTP 投递。脚本应在运行时读取这些配置，不新增、复制或打印 SMTP Token。

## 范围

### 监控项

1. **号池可用性**
   - 号池分母只包含 `status=active && schedulable=true` 的账号；人为停用或不可调度的账号不应降低告警比例。
   - 账号是否可用以 Sub2API `/admin/ops/account-availability` 的 `is_available` 为准。
   - 可用率为 `available / eligible * 100`。

2. **模型可用性**
   - 复用 Sub2API 渠道监测结果，不在脚本中重复构造模型请求。
   - 统计所有启用渠道的主模型与附加模型当前状态。
   - `operational` 计为可用，其他状态计为不可用。
   - 监测结果超过 `max(3 × interval_seconds, 15 分钟)` 未更新时，视为突发监控故障。

3. **额度使用率**
   - 对 active、schedulable 的 `oauth` / `setup-token` 账号调用主动额度查询。
   - 递归读取响应中的所有 `utilization` 数值，取每个账号和全局最大值。
   - 任一窗口使用率 `>= 80%` 即告警。
   - 单个账号额度接口不支持时记录失败但继续检查其他账号；所有候选账号都无法读取时视为监控故障。

4. **突发问题**
   - Sub2API 登录、账号列表、实时可用性或渠道监测接口失败；
   - 渠道监测数据过期；
   - 所有候选账号的额度检查均失败；
   - 脚本内部出现未处理异常。

### 通知

- 告警条件：号池可用性 `< 80%`、模型可用性 `< 80%`、最大额度使用率 `>= 80%`，或出现突发问题。
- 调度周期固定为 5 分钟；异常持续期间每次运行都发一封邮件，因此约每 5 分钟提醒一次。
- 异常全部解除后只发送一封恢复邮件。
- 正常且上次也是正常时不发邮件。
- 收件人来自权限为 `0600` 的本机环境文件，不写入仓库。
- SMTP 配置和 Token 每次从 new-api 数据库读取，不输出到日志和状态文件。

## 安全与可靠性

- 脚本只使用 Python 标准库、Docker CLI 和容器内现有 `psql`，不安装第三方依赖。
- 通过 `flock`/文件锁避免上一次检查未结束时并发执行。
- HTTP 请求、Docker 命令和 SMTP 连接都必须有超时。
- 状态文件以临时文件加原子替换写入。
- 日志不得包含管理员密码、JWT、SMTP Token、API Key 或完整凭据。
- 不修改 Sub2API 账号、渠道监测配置或额度状态；所有管理 API 调用均为读取操作。
- 不删除、重启或重建现有业务容器。

## 非目标

- 不自动购买、导入、启用或禁用账号。
- 不自动恢复限流账号。
- 不把大模型或通用 Agent 放进关键告警链路。
- 不新增公网管理接口。
- 不以七日历史可用率代替当前模型可用率；历史值只在邮件中作为上下文。

## 验收标准

1. 单元测试覆盖阈值边界、停用账号排除、额度递归解析、过期监测、持续告警和恢复通知。
2. `--dry-run` 在生产服务器能读取真实数据并生成报告，但不发送邮件。
3. `--test-email` 能通过 new-api 当前 SMTP 配置向指定收件人发送测试邮件。
4. 定时任务每 5 分钟运行，服务器重启后仍由用户 crontab 自动恢复。
5. 在生产当前异常基线下能发送告警邮件；服务容器保持运行且健康。
