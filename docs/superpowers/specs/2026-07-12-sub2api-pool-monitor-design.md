# Sub2API 分组感知号池邮件监控规格

日期：2026-07-12

## 目标与拓扑

Sub2API 是 new-api 的上游。监控对象不是 Sub2API 全局所有账号或所有渠道，而是 **new-api 当前使用的第一个 Sub2API API Key（ID=1）所绑定的分组**。

脚本每 5 分钟读取该 Key 当前分组，并按分组执行不同逻辑。异常持续期间每 5 分钟通过 new-api 现有 Resend SMTP 配置发信，恢复后发一封恢复邮件。

## 身份分类

- `type=apikey`：中转站上游账号，可提供正常文字模型，但不作为自有生图额度来源。
- `type=oauth` 或 `type=setup-token`：用户自己导入的账号，可提供图片模型，并能读取额度使用率。
- 只处理目标分组中 `status=active && schedulable=true` 的账号。

## 分组规则

### 自建池

1. 找出目标分组中的中转站账号，调用 Sub2API 自带的 `/admin/accounts/:id/test` 渠道测试能力。
2. 按顺序测试，任一中转站账号成功即判定正常文字模型可用，并停止继续探测，减少上游消耗。
3. 对该组所有自有账号调用主动 usage 接口，读取每个响应中的全部 `utilization`，以该账号最大窗口使用率表示账号当前消耗。
4. 只要至少一个自有账号使用率 `<100%`，即判定图片账号池仍可用。
5. 当所有可读自有账号都达到 100%，同时中转站测试成功时，邮件必须明确写：

   ```text
   现在正常的文字模型还能用，但是图片模型已经不能用了。
   ```

6. 所有中转站账号均测试失败时，提醒正常文字模型可能不可用。

### 自建安全使用

1. 该组预期只包含自有账号；发现中转站账号视为配置异常。
2. 查询组内所有自有账号额度。
3. “组总用量”必须按账号总额度加权，不能对百分比做算术平均。每个账号配置额度权重，先计算 `额度总量 × utilization` 得到已用量，再用总已用量除以总额度。
4. 组总用量 `>=80%` 时发出补号警告；任一在组账号缺少额度总量配置时停止计算并告警，禁止回退到等权平均。
5. 组总用量 `<80%` 时不因单个账号超过 80% 单独告警。

### 其他分组

如果 Key ID=1 被绑定到未定义规则的其他分组，发送配置异常邮件，不猜测业务语义。

## 突发问题

- 无法登录 Sub2API；
- 无法读取账号、分组或 API Key 绑定；
- 找不到 Key ID=1；
- 目标分组所有自有账号额度均无法读取；
- 自建池没有可测试的中转站账号；
- 自建安全使用组混入中转站账号；
- 脚本内部未处理异常。

## 邮件与状态

- 异常持续时每次 5 分钟调度都发送邮件；
- 异常全部解除后只发送一封恢复邮件；
- 正常且上次也正常时不发送邮件；
- SMTP 设置每次从 new-api PostgreSQL `options` 表读取；
- Sub2API 管理凭据每次从运行容器环境读取；
- 不在仓库、脚本、状态文件或日志中写入任何密码、Token 或 API Key 明文。

## 验收标准

1. 单元测试覆盖自建池文字可用/图片可用、图片池全部耗尽指定文案、中转探测短路、安全使用组加权用量 80% 边界、安全组混入中转账号及额度接口全部失败。
2. 生产 dry-run 能识别 Key ID=1 当前绑定的真实分组。
3. 当前自建池下，中转站测试成功且 4 个自有账号均未耗尽时，报告为正常，不发送错误的全局渠道可用率告警。
4. 定时任务每 5 分钟执行，服务器重启后由 deploy 用户 crontab 自动恢复。
